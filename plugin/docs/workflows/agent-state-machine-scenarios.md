# Agent state-machine scenario matrix

This matrix is the durable scenario boundary for the 14 orchestration Agents.
It describes observable handoffs and terminal outcomes; the owning Skills,
Rules, Hooks, and Shared Contracts remain the procedure sources of truth.

A scenario is valid only when repository identity, task scope, and the current
revision or pull-request head are explicit. A stale or conflicting identity is
never repaired by inference. A partial or unverified external result stops the
current run and preserves the first safe resume state.

## Cross-host execution coverage

The same state and handoff scenarios must be smoke-tested externally for
Cursor, Codex, and Claude. The minimum representative set is:

- issue creation and refinement, including bounded requirements dialogue;
- preparation, delivery, Draft PR publication, and Ready-for-Review;
- review, review-fix compatibility routing, feedback full/fix/follow_up,
  and CI-fix;
- product planning through publication and parent-tracker synchronization,
  including open, merged, and closed child states;
- issue reprioritization and issue closure;
- integration with stale-head, rebase-required, merge, closure, and cleanup
  branches.

The host smoke tests must assert the declared status rather than model prose:
happy-path completion, blocked identity, denied authorization, partial or
unverified external result, and safe resume. No host test may treat the
absence of the repository-local Node/Vitest workspace as a successful test
run.
